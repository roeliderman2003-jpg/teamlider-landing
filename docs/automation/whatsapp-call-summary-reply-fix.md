# תיקון: סיכום שיחה שלא משיב על הודעת ההקלטה (Make – "שיחות מוקלטות")

## הבעיה
האוטומציה **"שיחות מוקלטות"** (Make) שולחת לקבוצת הווצאפ שתי הודעות עבור כל הקלטה:

1. **קובץ ההקלטה** – נשלח דרך מודול Green API `Send a File` (SendFileByUpload).
2. **סיכום השיחה** (תמלול + ניתוח GPT) – נשלח דרך מודול Green API `Send a Message`.

הכוונה: הודעת הסיכום אמורה להישלח כ**תגובה (Reply/Quote)** על הודעת קובץ ההקלטה, כך שהסיכום מוצמד להקלטה בקבוצה. בפועל הסיכום נשלח כהודעה עצמאית ולא כתגובה.

## שורש הבעיה
במודול `Send a Message` ששולח את הסיכום, השדה **`Quoted Message Id`** נשאר ריק.
ב-Green API, תגובה על הודעה קיימת נעשית **אך ורק** ע"י מילוי `quotedMessageId` במזהה ההודעה שאליה רוצים להשיב. כשהשדה ריק – ההודעה נשלחת רגיל, בלי Reply.

## התיקון
למפות את `Quoted Message Id` של מודול הסיכום למזהה ההודעה שמחזיר מודול שליחת הקובץ:

```
Quoted Message Id  =  {{34.idMessage}}
```

- `34` = מודול `Send a File` (שליחת קובץ ההקלטה), שרץ ראשון ולכן ה-`idMessage` שלו כבר קיים.
- `idMessage` = שם שדה הפלט של Green API למזהה ההודעה שנשלחה (מאומת מול תרחיש "voice center" שכבר משתמש ב-`{{...idMessage}}`).

## שלבים בממשק Make
1. לפתוח את התרחיש **"שיחות מוקלטות"**.
2. ללחוץ על מודול **Green API → Send a Message** (זה שאחרי "תמלול" ו"סיכום שיחה", ה-Message שלו הוא תוצאת הסיכום).
3. לפתוח את השדה **Quoted Message Id** ולמפות אליו את `idMessage` של מודול **Send a File** (או להקליד `{{34.idMessage}}`).
4. לשמור (**OK** → **Save**).
5. **להפעיל את התרחיש** – כרגע הוא כבוי (Inactive); בלי הפעלה השינוי לא ייכנס לתוקף.

## אימות
להריץ "Run once" (או להעלות הקלטת בדיקה לתיקיית הדרייב הנצפית) ולוודא בקבוצת הווצאפ שהודעת הסיכום מופיעה כ-**תגובה מצוטטת** מתחת לקובץ ההקלטה.

> הערה: אם בהרצה מסוימת שליחת הקובץ נכשלת, `idMessage` יהיה ריק והסיכום פשוט יישלח בלי ציטוט (ללא שגיאה) – התנהגות נסבלת.
